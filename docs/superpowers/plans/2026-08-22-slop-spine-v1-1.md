# slop-spine v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the editor usable for actual drawing — undo, grayscale values, and the controls that exist in the model but were never exposed.

**Architecture:** Three small tasks on top of a complete v1. No new subsystems; each wires existing capability to the UI. Task 15 depends on Task 13 (clear-layer must be undoable), so the order is fixed.

**Tech Stack:** Unchanged — Svelte 5 runes, TS, Vite, Tailwind 4, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-22-slop-spine-design.md`

## Why this exists

v1 shipped a drawing app with **no undo** and **only black paint**. Neither was a scoping decision — both were omissions from the spec, which listed neither in its "In" nor "Out" sections.

Undo is close to load-bearing for the project's premise. The whole pitch is *keep drawing after you have rigged*, but nobody experiments freely when every stroke is permanent. The eraser is not a substitute: it removes pixels, it cannot restore a bad stroke laid over existing art.

Black-only paint blocks the house style outright. `slops/docs/principles.md` commits to "loose ink linework, grainy fills, on white," and the technique is white-fill-under-black-outline — which needs white.

## Global Constraints

Same as v1, plus what follows.

- **Ethos: rough, indie, deliberately imperfect.** Ship the dumb version that mostly works; upgrade only when a failure is visible on screen. Hardcode defaults — one slider beats seven fields. If a task starts feeling thorough, that is a smell.
- **Test only what cannot be eyeballed.** All three tasks are UI. **No unit tests.** Verified by driving real Chrome.
- **Every task runs `npm test` AND `npm run check` before committing, both clean.** The existing 47 tests must still pass.
- **`tsconfig.json` is strict**; **runes mode enforced** (`$state`/`$derived`/`$effect`).
- Canvas **2048×2048**, y-down. Bones canvas-absolute.
- **Grayscale only, not RGB.** `slops/docs/principles.md` produces grayscale source art and applies per-zone tint at runtime via shader; RGB source would fight the tint pass. Widening to full colour later is a one-line change to the swatch list.
- **Nothing in the rig may be stored per-vertex.** Undo restores *pixels*; mesh and weights regenerate from them as always.
- **`layer.canvas` must stay transparent where nothing is drawn.** Export trims on alpha; an opaque-white layer would trim to the full page and blow up the atlas.

## Task 13: Undo and redo

**Files:**
- Create: `src/core/history.ts` (copied), `src/state/history.svelte.ts`
- Modify: `src/lib/draw-dispatch.ts`, `src/lib/Toolbar.svelte`, `src/lib/Canvas.svelte`

**Interfaces:**
- Consumes: `markLayerDirty(id)` from `src/state/doc.svelte.ts`
- Produces: `history` store with `push(cmd)`, `undo()`, `redo()`, and **reactive** `canUndo` / `canRedo`

- [ ] **Step 1: Copy the history module**

```bash
cp /Users/meigo/Projects/slop/slop-animator/src/anim/history.ts src/core/history.ts
```

It has no imports, so the copy closes. **Only import paths may be edited** — the rule that has held for every copied module on this branch.

Its API: `class History` with `push(cmd)`, `undo()`, `redo()`, an `onChange?` hook, and byte-budgeted eviction; plus `pixelCommand(undo, redo, before, after)` which computes `bytes` from the two `ImageData`s.

- [ ] **Step 2: Capture the dirty rect, NOT the whole canvas**

This is the one decision that determines whether undo is usable.

`DEFAULT_HISTORY_BYTES` is 256MB, sized for slop-animator's 1920×1080 frames. Our canvas is 2048×2048, so one full-canvas `ImageData` is `2048 × 2048 × 4` = **16MB**, and `pixelCommand` stores two — 32MB per stroke. That is **8 strokes** before eviction starts discarding history.

So capture only the region a stroke touched:

- Before a stroke begins, record nothing yet.
- Track the stroke's bounding box as points arrive, padded by the brush radius.
- On stroke end, `getImageData` that rect **once** for `after`, and take `before` from a snapshot of the same rect captured at stroke start.

A snapshot at stroke start means grabbing the rect before you know how big it is — so take the simple route: snapshot the full canvas into an offscreen copy at stroke start (a `drawImage` to a scratch canvas, cheap, no `getImageData`), and at stroke end read `before` out of the scratch at the final rect and `after` out of the live layer at the same rect. One scratch canvas reused for every stroke.

Fill and clear-layer capture their own affected rect the same way — a fill's rect is the whole canvas, and that is fine because fills are rare.

- [ ] **Step 3: Write `src/state/history.svelte.ts`**

A module-level `History` instance, plus `canUndo`/`canRedo` mirrored into `$state` through its `onChange` hook.

The copied module's own comment explains why the mirror is required: a plain class getter is not a reactive dependency, so a button bound directly to `history.canUndo` would never re-render.

- [ ] **Step 4: Undo and redo must bump `layer.revision`**

Each command's `undo` and `redo` restores its `ImageData` with `putImageData`, then calls `markLayerDirty(layerId)`.

**Without this the rig goes stale against the art**: `deriveSlot` caches on `(layer.revision, density, boneSignature)`, so an undo that changes pixels without bumping revision leaves the mesh and weights describing a drawing that no longer exists — silently, with a well-formed export. That is the failure class this codebase produces; do not skip it.

- [ ] **Step 5: Wire the commands**

Push one command per completed stroke (not per pointer-move), one per fill, one per erase stroke. Erasing is a pixel change like any other — same command shape.

- [ ] **Step 6: Keyboard and buttons**

`Cmd/Ctrl+Z` undo, `Shift+Cmd/Ctrl+Z` redo. Undo/Redo buttons in the toolbar, disabled from the reactive `canUndo`/`canRedo`.

Ignore the shortcuts when focus is in a text input, or renaming a layer will eat them.

- [ ] **Step 7: Verify in real Chrome**

Playwright from the session scratchpad; do not add it to `package.json`. Prove:
- a stroke, then undo, restores the prior pixels (compare an opaque-pixel count before/after)
- `layer.revision` changed on undo, and `deriveSlot` returned a **new mesh** afterward
- redo re-applies
- undoing an erase brings pixels back
- ~20 strokes in a row does not evict early — report the observed retained-command count, which is what proves Step 2 worked

- [ ] **Step 8: Commit**

```bash
git add -A && git commit -m "feat: undo and redo for pixel edits"
```

## Task 14: Grayscale values and a checkerboard page

**Files:**
- Modify: `src/state/ui.svelte.ts`, `src/lib/Toolbar.svelte`, `src/lib/draw-dispatch.ts`, `src/lib/Canvas.svelte`

**Interfaces:**
- Produces: `ui.brushValue` — a hex string from a fixed grayscale ramp

- [ ] **Step 1: Add the value to UI state**

`brushValue: "#000000"` in `src/state/ui.svelte.ts`.

- [ ] **Step 2: A swatch row in the toolbar**

Six fixed swatches, no picker, no custom field:

```
#000000  #404040  #808080  #b0b0b0  #e0e0e0  #ffffff
```

Selected swatch gets a visible outline. That is the whole control.

- [ ] **Step 3: Wire it to brush and fill**

`src/lib/draw-dispatch.ts` currently hardcodes `const FILL_COLOR = "#000000"` and passes it as the brush `color`. Replace both uses with `ui.brushValue`.

The eraser is unaffected — it composites `destination-out` and ignores source colour entirely.

- [ ] **Step 4: Replace the white page with a checkerboard**

This is required by Step 2, not decoration. Once white is paintable, a white stroke on a white page is invisible — and the house technique paints white constantly, under black outlines.

In `Canvas.svelte`'s redraw, replace the flat `#fff` fill of the document rect with a checkerboard drawn in document space: two light grays, squares around 32 document units. Keep the existing border, including its `lineWidth = 2 / viewport.zoom` so it stays a constant 2px on screen.

Draw it with a `createPattern` off a small offscreen tile rather than looping thousands of `fillRect` calls at low zoom.

**This is a screen-only fill.** It must never touch a `layer.canvas` — export trims on alpha, and a checkerboard baked into a layer would trim to the full 2048×2048 page and destroy the atlas.

- [ ] **Step 5: Verify in real Chrome**

- draw with each of the six values and read back the pixel colour for each
- a white stroke is visibly distinguishable from empty page (screenshot)
- fill uses the selected value
- after drawing white, an untouched pixel is still **alpha 0** — read the alpha byte explicitly, because white paint and transparency look identical and only the alpha channel tells them apart
- screenshot path in the report

- [ ] **Step 6: Make the verify page assert transparency, permanently**

Transparency is a hard requirement of the export — characters composite over backdrops — and it is
the one property that **cannot be checked by looking**, because white paint and empty space are
visually identical. This task adds two new ways to break it (a paintable white, and a checkerboard
that must never reach a layer), so it also adds the guard.

`verify.html` already runs the real export chain. Extend `src/verify/main.ts` to decode the exported
`skeleton.png` and count alpha, then include the result in the `[verify]` line and `window.__verify`:

```ts
const alpha = { transparent: 0, opaque: 0, partial: 0, cornerAlpha: 0 };
```

Report `transparent`, `opaque`, `partial` and the top-left `cornerAlpha`. **Log `[verify] ALPHA
FAIL` if `cornerAlpha !== 0` or `transparent === 0`** — either means a background got baked in.

Measured baseline on the current fixture, for comparison: a 2048×1024 atlas, 1,882,132 transparent
px (89.8%), 213,720 opaque, 1,300 partial from antialiased edges, corner alpha 0.

- [ ] **Step 7: Commit**

```bash
git add -A && git commit -m "feat: grayscale value swatches and a checkerboard page"
```

## Task 15: Expose what the model already has

**Files:**
- Modify: `src/lib/LayerPanel.svelte`, `src/lib/Toolbar.svelte`, `src/state/doc.svelte.ts`

Three controls whose underlying capability already exists, is persisted, and is honoured by the renderer or exporter — with no way to reach it.

- [ ] **Step 1: Layer opacity**

`Layer.opacity` is in `RigDocument`, survives save/load, and is applied by `Canvas.svelte`'s redraw. Add a slider to the layer row in `LayerPanel.svelte`.

**Already checked and ruled — do this, do not re-investigate.** `opacity` is applied by
`Canvas.svelte` (`ctx.globalAlpha`) and persisted by `project-file.ts`, but does **not** appear in
`src/export/bundle.ts`. So today it is view-only: a layer at 30% renders faded and exports fully
opaque. Persisted document state that silently fails to reach the output is exactly this project's
recurring bug shape, so make it honest — but **not** by baking alpha into the exported PNG, which is
destructive and would force a re-export of artwork every time opacity changes.

Instead emit it as **Spine slot alpha**, which the runtime already understands. A Spine slot accepts
`"color": "rrggbbaa"`; the reference rig omits it, which means default opaque white. So in
`src/export/spine-json.ts`, when a layer's opacity is below 1, emit `color` on its slot as
`"ffffff" + <two-hex-digit alpha>`; omit the field entirely at full opacity so ordinary characters
stay byte-clean.

This adds `src/export/spine-json.ts` to the files this task owns. Keep the change to those three
lines — no slot tinting, no colour control, alpha only.

- [ ] **Step 2: Fit view**

`viewport.fitView()` exists and runs once at mount. Add a toolbar button calling it, so panning off into the void is recoverable.

- [ ] **Step 3: Clear layer**

A button that clears the selected layer to fully transparent (`clearRect`, never a white fill), bumps `revision`, and **pushes an undo command** using Task 13's history — clearing a layer without undo is the most destructive thing in the app.

- [ ] **Step 4: Verify in real Chrome**

- opacity slider changes on-screen rendering, and the value survives a reload
- fit view recentres after panning away
- clear layer empties the layer, leaves an untouched pixel at **alpha 0**, and is undoable
- report whether export honours layer opacity (Step 1's question)

- [ ] **Step 5: Commit**

```bash
git add -A && git commit -m "feat: layer opacity, fit view, clear layer"
```

## Task 16: The rig overlay shows the whole character

**Files:** Modify `src/lib/Canvas.svelte`, `src/lib/RigOverlay.ts`

`Canvas.svelte` currently derives and draws the mesh for **only the selected layer's slot**. Every
other part of the character shows no mesh at all.

That is not merely inconvenient — **it hides the one failure mode the weighting is known to have.**
The spec accepts that Euclidean distance-to-segment bleeds across spatial gaps (an arm hanging beside
a hip picks up hip weight) and names geodesic distance as the deferred fix. Bleed is a relationship
*between two parts*, so it is invisible while you can see one part's mesh at a time. Rigging is
inherently about how parts meet; the overlay should show that.

- [ ] **Step 1: Draw every visible layer's mesh**

Loop visible layers, `deriveSlot` each, draw all their triangles dimmed; draw the selected layer's
mesh at full strength on top so it stays legible.

`deriveSlot` is memoised per slot on `(revision, density, boneSignature)`, so after the first frame
this costs a cache hit per layer. Do not add batching or throttling until it visibly stutters.

- [ ] **Step 2: Weight tint across every slot bound to the selected bone**

Today the tint is scoped to the selected layer. Tint **every** slot that binds the selected bone.
This is the step that makes bleed visible: select a hip bone and any weight it is stealing from the
arm lights up in the arm's mesh, in place, where you can see it and fix it upstream by moving a bone
or adjusting the bind.

- [ ] **Step 3: Verify in real Chrome**

Two overlapping layers bound to different bones. Show that both meshes render, that selecting a bone
tints vertices in every slot bound to it, and — ideally — capture a case where a bone tints vertices
in a part it should not influence. That screenshot is the argument for geodesic when someone
eventually wants it.

- [ ] **Step 4: Commit**

```bash
git add -A && git commit -m "feat: rig overlay shows all meshes and cross-slot weight tint"
```

## Task 17: Per-slot mesh density, with the global value as the default

**Files:** Modify `src/rig/document.ts`, `src/rig/derive.ts`, `src/lib/RigPanel.svelte`, `src/persist/project-file.ts`

**Depends on Task 16** — a per-part control is hard to judge while you can only see one part's mesh.

The spec deferred this: *"no per-slot mesh params until one character needs them."* The first real
character needs them, and the reference rig has needed them all along.

Measured from the hand-rigged `sloppets/spine/test-char/char.json`, density varies **16× across
parts** — Mouth 652 px/vertex, Arm b 1,970, Eyes 2,477, Head 5,266, Body 10,586. The pattern tracks
**how much a part deforms**, not how big it is: the mouth is finely meshed because it is sculpted for
visemes, the body is nearly rigid and barely needs vertices, arms bend at one joint and sit between.

One global value cannot express that. Too coarse and thin parts collapse (Task 7's render: a 300×80
arm tapered to a wedge at density 48). Fine enough for hair and the torso gets hundreds of useless
vertices, every one of which is re-weighted on each bone drag.

- [ ] **Step 1: Add the optional override**

`density?: number` on `Slot` in `src/rig/document.ts`. Optional, so absent means "use the document
default" and every existing project file loads unchanged.

- [ ] **Step 2: Effective density in the derivation**

`const density = slot.density ?? doc.density;` — and it must go into the **mesh half** of the cache
key in `src/rig/derive.ts`, which is currently `${layer.revision}|${doc.density}`. Get this wrong and
changing a slot's density silently returns the old cached mesh.

- [ ] **Step 3: RigPanel shows the selected slot's effective value**

The existing density slider becomes per-slot: it shows `slot.density ?? doc.density`, and moving it
sets the override on that slot. Add a small "reset to default" affordance so an override can be
cleared back to inheriting.

Keep the document-level default settable too — it is what new layers start from.

- [ ] **Step 4: Persist it**

Carry `density` through `DocumentJson`'s slot entries in `src/persist/project-file.ts`. Absent stays
absent; do not write `undefined` into the JSON.

- [ ] **Step 5: Verify in real Chrome**

Two layers of very different thickness — a thick torso and a thin strand. Show that a per-slot
density change regenerates **only that slot's** mesh (vertex count changes for it, unchanged for the
other), that it survives a save/load round-trip, and that clearing the override returns it to the
document default.

- [ ] **Step 6: Commit**

```bash
git add -A && git commit -m "feat: per-slot mesh density overriding the document default"
```

## Self-review notes

**Spec coverage.** This plan closes two spec omissions (undo, drawable values) and one consequence of the second (checkerboard). It adds nothing not traceable to a gap found by using the app.

**Deliberately not included.** Eyedropper, brush presets, layer groups, custom colour entry, opacity for the eraser, redo-tree — none has been asked for. Full RGB is deliberately excluded per the grayscale pipeline.

**Known risk.** Task 13's dirty-rect capture is the only piece with a real chance of being got wrong, and its failure mode is quiet: undo works fine in a short test and evicts history after a handful of strokes in real use. Step 7's ~20-stroke check exists specifically to catch that.
